## 1. Objective
На сайте присутствует уязвимость внедрения команд ОС в компоненте проверки наличия товара, необходимо узнать имя пользователя

## 2. Reconnaissance
- Зашел на сайт, в первом попавшемся товаре нашел нужный мне компонент с уязвимостью

## 3. Exploitation
1. С помощью Burp Interceptor перехватил запрос проверки наличия товара
2. В этом запросе увидел строчку с параметрами 'productId' и 'storeId'
3. Добавил в значение параметра 'productID' команду linux-shell определяющую пользователя 'whoami' с помощью разделителей '|'
4. В ответе моя команда выполнилась и сервер вернул имя пользователя, лабораторная работа решена 

**Payloads:**
```text
productId=4|whoami|&storeId=1
```

**Почему это сработало:**  
shell разбил строку по разделителю | и выполнил 'whoami' как отдельную команду.

## 4. Result
Имя пользователя - 'peter-NaWIuq', лабораторная работа решена

## 5. Key Takeaway & Remediation

**Что я узнал:**  
Если приложение подставляет значения параметров в shell-команду без валидации, атакующий может выполнить произвольные команды ОС через разделители

**Как защитить:**
1. Строгая валидация (whitelist)
