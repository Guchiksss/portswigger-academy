## 1. Objective
Удалить пользователя `carlos`, найдя и использовав незащищенную административную панель, URL которой скрыт на странице.

## 2. Reconnaissance
- Открыл главную страницу сайта.
- Открыл DevTools для анализа клиентского кода.

## 3. Exploitation
1. Изучил исходный код страницы и нашел встроенный JavaScript (inline script).
2. Обнаружил строку кода, которая динамически создает ссылку на админку: `adminPanelTag.setAttribute('href', '/admin-xxxxxx');`
3. Скопировал этот случайный URL (например, `/admin-fbzb19`).
4. Перешел по найденному URL в браузере.
5. Удалил пользователя `carlos` из панели управления.

**Payload/URL:** 
```text
/admin-fbzbi9
```
**Почему это сработало:**  
Разработчики использовали "security by obscurity" — спрятали URL админки за случайной строкой (`fbzb19`). Но этот URL находился во встроенном JavaScript, который выполняется в браузере каждого пользователя. Любой может открыть исходный код страницы и найти его.

## 4. Result
Доступ к административной панели получен, carlos удален, флаг получен

## 5. Key Takeaway & Remediation
**Что я узнал:** 
Security by obscurity - это то же самое, что оставить дверь в дом открытой. Не стоит прятать unpredictable URL в client-side code
**Как защитить:**
1. Реализовать проверку прав на стороне сервера (server-side): даже зная URL, пользователь без роли администратора должен получать ошибку 403 Forbidden
3. Никогда не хранить чувствительные пути, токены или логику проверки прав в клиентском коде (JavaScript, HTML)
