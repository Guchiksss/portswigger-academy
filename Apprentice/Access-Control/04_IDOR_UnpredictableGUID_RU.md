## 1. Objective
Дан сайт с уязвимостью горизонтального повышения привилегий на странице учетной записи пользователя, требуется найти GUID карлоса и получить его API Key

## 2. Reconnaissance
- Зашел на сайт с блогами разных людей, начал листать посты и искать упоминания карлоса среди комментаторов - ничего не нашел
- Залогинился на сайт, в личном кабинете пишется твой API Key (понял где его искать)
- Снова начал читать посты и среди авторов нашел карлоса
- Перешел на его страницу и нашел его GUID

## 3. Exploitation
1. Использовал IDOR (поменял свой GUID на GUID карлоса в личном кабинете)

**Payload:**
```text
userId=4fc6c347-fe1c-4c27-a045-ad30c9170262
```

**Почему это сработало:**  
Сайт выдал чужой GUID на странице автора поста

## 4. Result
Получил доступ к аккаунту карлоса, получил его API Key, лаборатория решена

## 5. Key Takeaway & Remediation

**Что я узнал:**  
Сложный GUID не служит защитой от IDOR, если сайт сам выдает его в открытом доступе, при том что есть уязвимость горизотального повышения привилегий


**Как защитить:**
1. При каждом запросе к ресурсу сервер должен проверять на backend-уровне, что запрашиваемый ID принадлежит текущему авторизованному пользователю
2. Не раскрывать внутренние идентификаторы пользователей (GUID, ID) в публично доступных местах: URL страниц, метаданных, API-ответах
