## 1. Objective
Получить доступ к аккаунту администратора и удалить карлоса

## 2. Reconnaissance
- Зашел на сайт онлайн магазина, просмотрел товары никаких зацепок нет
- Проверил robots.txt — отсутствует
- Залогинился под wiener:peter
- Проверил /admin — доступ запрещен, но заметил упоминание "administrator"
- Обнаружил параметр userid в URL личного кабинета
- Получил доступ к аккауну carlos через замену userid — нашел его пароль
- Попытка использовать пароль carlos для доступа к /admin не удалась

## 3. Exploitation
1. Изменил `userid=wiener` на `userid=administrator`
2. Получил доступ к аккаунту администратора
3. Через DevTools извлек пароль администратора из замаскированного поля
4. Залогинился под администратором, получил доступ к /admin
5. Удалил пользователя carlos

**Payload:**
```text
userid=wiener -> userid=administrator
```

**Почему это сработало:**  
На сайте присутствует уязвимость IDOR, позволяющая менять параметр userid в URL и получать доступ к чужим аккаунтам без проверки прав

## 4. Result
Получил пароль от аккаунта администратора, получил доступ к админ-панели, удалил карлоса

## 5. Key Takeaway & Remediation

**Что я узнал:**  
Горизонтальная уязвимость (IDOR) может стать ступенькой для вертикальной эскалации привилегий, если attacker получает доступ к аккаунту администратора. Также пароли не должны храниться в замаскированных полях на странице личного кабинета - это создает ложное чувство безопасности.

**Как защитить:**
1. Реализовать server-side валидацию: проверять права доступа к аккаунтам на бэкенде, а не доверять параметру userid из URL
